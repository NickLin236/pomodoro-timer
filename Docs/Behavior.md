# Version 1.2.2 behavior

Focus defaults to 25 minutes, break to 5 minutes, and cycles to 4. The general timer defaults to 5 minutes. Pomodoro includes the final break. Automatic transitions start at their scheduled boundaries, even when a callback arrives late. Skip advances immediately without a completion notification; a paused skip leaves the next phase paused. Reset restores the saved configuration and clears the current session. Start after completion captures the current input as a new session.

Each Pomodoro focus/break and the countdown may last at most 7 days. The UI accepts whole positive focus/break minutes (1–10,080), 1–1,000 cycles, and a positive countdown up to 168 hours. The core retains millisecond precision. Values are checked before multiplication or deadline addition. A total Pomodoro schedule can span up to 14,000 days. Time displays round positive fractional seconds up and include hours when necessary. Invalid input does not change active timers.

Configuration changes affect new sessions. Paused and running sessions keep their captured durations/cycles. Reset uses the saved setup. Each timer has its own state; they share one countdown scheduler. Countdown callbacks run at most once per second and stop when neither timer is running and no notification retry is pending. A separate taskbar placement monitor checks geometry once per second while taskbar status is requested, including while paused or waiting for a free gap. It stops when status is inactive, disabled, or destroyed; geometry checks do not advance paused timers or write state. Starting, pausing, resuming, skipping, resetting, transitions, settings changes, and exit trigger persistence. Displays do not write files every second.

Running timers use QueryInterruptTime, a monotonic clock that includes suspended time. It is resolved dynamically for SDK compatibility; GetTickCount64 provides a defensive fallback at system timer resolution. The controller projects UTC from that anchor. A detected wall-clock jump of at least one second shifts persisted running deadlines to retain elapsed-time behavior. UTC deadlines are used after a real exit. Moving the clock backward while exited can therefore restore more remaining time than the nominal duration; pausing preserves that full amount. Time-zone and daylight-saving changes do not affect UTC. Offline elapsed time across shutdown plus manual clock adjustment cannot be independently verified.

Late processing reconciles every overdue phase against its original scheduled boundary. For 2-minute focus / 1-minute break with at least two cycles, reopening four minutes after Start enters cycle 2 focus with one minute left. Paused state restores its saved remaining time even after reboot. Late/resume/restart notifications are consolidated into one current summary per affected timer. Normal processing requests a local Windows notification at every automatic phase/timer completion. Reset during a break clears that session; starting again begins cycle 1 focus with fresh notification bookkeeping and the full configured break after focus. Reset does not skip a break in a later session.

The state/settings format remains version 1. Version 1.1 adds the optional boolean `showTaskbarStatus`; existing settings without that field load it as true. Legacy `backgroundMode` values remain readable for compatibility, but no longer change the Close/Minimize behavior and are not exposed as a UI choice. Unknown schema versions are rejected visibly rather than guessed. Missing files use defaults; malformed/invalid primary files fall back to validated backups. If neither is valid, safe defaults and a warning are shown. Saves use same-directory temporary files, flushing, atomic replacement, and validated backup preservation. A failed write leaves an error visible; persistence is not guaranteed until the underlying error is resolved.

Notifications use native Windows ToastGeneric content. Pomodoro notifications describe only the completed focus/break, cycle, and current Pomodoro state; countdown notifications describe only the countdown. Each affected timer has its own notification tag so later notifications replace its old message rather than accumulating a phase history. The **Dismiss** button removes the notification from Windows notification history without altering either timer. **Stop** resets only the timer session that produced the notification. Actions include the session identity, so clicking Stop on an old session's notification cannot stop a newer session or the other timer. Clicking the notification opens the relevant timer page.

Notification support is registered per user at application startup and retried when needed. The app creates a **Pomodoro Notifications** Start Menu shortcut with its application identity and a stub activator identity, and registers the `pomodoro-native` protocol to the quoted executable path. This supports notification actions when the app is already running or needs to reopen. No administrator access, service, companion executable, or additional download is required. Running a moved copy refreshes the registration to its new location.

A Windows settings lookup that returns `0x80070490` (Element not found) is treated as unavailable information rather than a disabled-notifications setting. The app still asks Windows to display the notification and reports any actual submission or asynchronous delivery error. Explicit disabled settings and other settings-lookup errors continue to stop the request with their diagnostic. This narrow handling follows the [reported Windows notification lookup failure](https://github.com/MicrosoftDocs/windows-dev-docs/issues/1431); it does not change Windows notification permissions.

Notification attempt sequences are saved before requesting Windows delivery. A synchronous failure is reported with setup, policy, or HRESULT details. Later Windows delivery failures are also reported in the status area through a thread-safe callback; callbacks and queued errors from reset/replaced notifications are retired. Synchronously rejected completion requests retry up to twice at five-second intervals, while that timer session remains current; Test notification can be requested again manually. Reset or a new session cancels its old retry. The scheduler can remain active briefly after completion to finish these retries. The retry queue is in memory: exiting does not preserve pending failed requests. A crash between saving an attempt and delivery can suppress a banner; exactly-once delivery is not promised. Windows notification settings and Focus Assist/Do not disturb may also suppress banners or sounds. Completion messages remain in the application status area until replaced by another action. Restoring an older backup can necessarily restore older notification bookkeeping.

Close, Alt+F4, and Exit all save and terminate the process. The notification icon and taskbar status panel are removed. Running sessions retain their persisted deadlines for recovery on a later launch; no live notification can run while the process is exited. If saving fails, the existing error/exit confirmation lets the user decide whether to quit without a successful save.

Minimize and background launch hide the main window in the notification area. Timers continue in the single application process. If the notification icon cannot be installed, the application retains a normal minimized taskbar button so it remains accessible. Windows controls whether the notification icon appears directly or in the hidden-icons overflow.

With **Show timer status in taskbar** enabled, an active focus or break displays its phase, remaining time, and cycle position near the notification area; an active countdown displays its remaining time. **Preferred taskbar timer when both are active** selects the source when both timers are running or paused. If that source is inactive, the other active timer is used. Paused sessions retain paused status when a safe slot exists. Idle/reset and final completion hide the panel when neither timer is active. The panel uses the primary horizontal taskbar and follows its visibility rather than creating a separate application button.

Placement uses visible occupied rectangles, clipped to the taskbar and relevant parent client areas. Foreign widgets are considered even when their raw bounds are taller or wider than the taskbar, their caption is unavailable, or they sit inside a task-list container. Explorer layout containers are not treated as occupied button space; application-button bounds are collected separately through accessibility. Top-level windows behind the taskbar do not become obstacles merely because an invisible frame border intersects its row.

The layout chooses the rightmost full-size gap at or to the left of the widget group, preserving horizontal clearance from occupied windows. It does not shrink the panel, resize Explorer, move Traffic Monitor, or reserve a taskbar band. The actual panel rectangle is checked before it is shown. If no safe gap exists, or application-button bounds are unavailable, the panel is hidden and a status message remains available in the main window. A crowded taskbar can therefore leave the panel hidden until space becomes available.

Application-button accessibility reads run asynchronously with bounded outstanding work and cached results; timer commands do not wait for an external process to answer. Application-button layout events invalidate cached bounds immediately; a read from an older layout generation cannot redisplay the panel. Stale, failed, unwatched, or unsupported button results leave the panel hidden until usable bounds can be established. A completed read can trigger a panel refresh, including while a timer is paused. The placement monitor also detects other windows moving after a pause, and placement availability changes refresh the main-window status. Windows 11 layouts are attempted when occupied bounds can be established but remain unverified. Vertical and unsupported taskbars report panel unavailability; timers remain usable through the normal window and notification icon. Actual placement, accessibility availability, auto-hide, DPI behavior, and coexistence with other programs require Windows desktop validation.

The main window still exposes its title and taskbar progress while visible. It uses the same timer-source selection as the text panel. Explorer restart restores the notification icon and reevaluates status-panel placement.

Startup is per-user, opt-in, and uses only the `PomodoroNative` value in `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, with a quoted executable path and `--background`. Registry errors leave the checkbox matching the last confirmed registration state. No service, scheduled wake-up, accounts, cloud sync, history charts, or network activity is included.
