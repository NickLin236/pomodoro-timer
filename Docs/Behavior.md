# Version 1.1 behavior

Focus defaults to 25 minutes, break to 5 minutes, and cycles to 4. The general timer defaults to 5 minutes. Pomodoro includes the final break. Automatic transitions start at their scheduled boundaries, even when a callback arrives late. Skip advances immediately without a completion notification; a paused skip leaves the next phase paused. Reset restores the saved configuration and clears the current session. Start after completion captures the current input as a new session.

Each Pomodoro focus/break and the countdown may last at most 7 days. The UI accepts whole positive focus/break minutes (1–10,080), 1–1,000 cycles, and a positive countdown up to 168 hours. The core retains millisecond precision. Values are checked before multiplication or deadline addition. A total Pomodoro schedule can span up to 14,000 days. Time displays round positive fractional seconds up and include hours when necessary. Invalid input does not change active timers.

Configuration changes affect new sessions. Paused and running sessions keep their captured durations/cycles. Reset uses the saved setup. Each timer has its own state; they share one Windows scheduler. Display callbacks run at most once per second and stop when neither timer is running. Starting, pausing, resuming, skipping, resetting, transitions, settings changes, and exit trigger persistence. Displays do not write files every second.

Running timers use QueryInterruptTime, a monotonic clock that includes suspended time. It is resolved dynamically for SDK compatibility; GetTickCount64 provides a defensive fallback at system timer resolution. The controller projects UTC from that anchor. A detected wall-clock jump of at least one second shifts persisted running deadlines to retain elapsed-time behavior. UTC deadlines are used after a real exit. Moving the clock backward while exited can therefore restore more remaining time than the nominal duration; pausing preserves that full amount. Time-zone and daylight-saving changes do not affect UTC. Offline elapsed time across shutdown plus manual clock adjustment cannot be independently verified.

Late processing reconciles every overdue phase against its original scheduled boundary. For 2-minute focus / 1-minute break with at least two cycles, reopening four minutes after Start enters cycle 2 focus with one minute left. Paused state restores its saved remaining time even after reboot. Late/resume/restart notifications are consolidated into one current summary. Normal processing requests one local shell notification at every automatic phase/timer completion.

The state/settings format remains version 1. Version 1.1 adds the optional boolean `showTaskbarStatus`; existing settings without that field load it as true. Legacy `backgroundMode` values remain readable for compatibility, but no longer change the Close/Minimize behavior and are not exposed as a UI choice. Unknown schema versions are rejected visibly rather than guessed. Missing files use defaults; malformed/invalid primary files fall back to validated backups. If neither is valid, safe defaults and a warning are shown. Saves use same-directory temporary files, flushing, atomic replacement, and validated backup preservation. A failed write leaves an error visible; persistence is not guaranteed until the underlying error is resolved.

Notification attempt sequences are saved before requesting shell delivery. A crash between those actions can suppress a banner; exactly-once delivery is not promised. Windows may also suppress banners or sounds. Completion messages remain in the application status area until replaced by another action. Restoring an older backup can necessarily restore older notification bookkeeping.

Close, Alt+F4, and Exit all save and terminate the process. The notification icon and Pomodoro status panel are removed. Running sessions retain their persisted deadlines for recovery on a later launch; no live notification can run while the process is exited. If saving fails, the existing error/exit confirmation lets the user decide whether to quit without a successful save.

Minimize and background launch hide the main window in the notification area. Timers continue in the single application process. If the notification icon cannot be installed, the application retains a normal minimized taskbar button so it remains accessible. Windows controls whether the notification icon appears directly or in the hidden-icons overflow.

With **Show Pomodoro status in taskbar** enabled, an active focus or break displays its phase, remaining time, and cycle position near the notification area. Paused Pomodoro sessions display paused status. Idle/reset and final completion hide the panel; the general countdown alone does not activate it. The panel attaches to the primary horizontal Windows 10 taskbar immediately left of Traffic Monitor when that window is detected, or left of the notification area otherwise. It follows the taskbar's visibility rather than creating a separate application button.

The panel is an overlay and does not reserve a taskbar band or resize Traffic Monitor or the application-button area. This avoids competing layout changes between the two applications, but it can cover application buttons on a crowded taskbar. Leave a gap or turn off **Show Pomodoro status in taskbar** if that occurs. Vertical taskbars and the modern Windows 11 taskbar are unsupported; the app reports panel unavailability and timers remain usable through the normal window/notification icon. Actual placement, auto-hide, DPI, and Traffic Monitor coexistence require Windows desktop validation.

The main window still exposes its title and taskbar progress while visible. Its selected indicator source chooses Pomodoro or the general timer when both are active; otherwise an active timer is used. This main-window indicator is separate from the Pomodoro text panel. Explorer restart restores the notification icon and reevaluates status-panel placement.

Startup is per-user, opt-in, and uses only the `PomodoroNative` value in `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, with a quoted executable path and `--background`. Registry errors leave the checkbox matching the last confirmed registration state. No service, scheduled wake-up, accounts, cloud sync, history charts, or network activity is included.
