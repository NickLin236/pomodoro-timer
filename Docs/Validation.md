Version 1.2.2 replaces the previous widget-anchor heuristics after the user reported continued overlap. The previous filter could reject a visibly occupied window because its original bounds extended beyond the taskbar. The new path collects clipped occupied rectangles, includes unknown foreign widgets, checks application-button bounds asynchronously, and searches for a full-size slot with horizontal clearance. It validates the actual panel rectangle before showing it and hides the panel when no safe slot or usable button bounds are available. Explorer and neighboring windows are not resized.

All five portable Release CTest suites pass in 0.75 seconds. The new `taskbar_layout` suite passes eight scenarios, including 12,000 randomized layouts compared with an independent slot search; coverage includes the reported geometry, clipped/oversized windows, multiple blockers, insufficient space, coordinate extremes, scaling, and actual-slot validation. The complete Windows application and all six test executables cross-compile; the final collector, event-hook, and DPI-coordinate changes are included in the successful build. Native regressions include a clipped foreign widget under a full-size WorkerW container, ancestor-client clipping, a fully occupied host that hides the panel, and restoring the panel after space is freed. A private native task-list/button fixture also exercises asynchronous accessibility reads, button collision, and recovery without querying Explorer. These native tests have been compiled, not executed here. No real Windows 1.2.2 placement, accessibility, DPI, auto-hide, or application-coexistence result is claimed in this Linux environment.

The taskbar placement monitor runs once per second while status is requested, including paused and no-room states; the countdown scheduler still stops without a running timer or pending notification retry. Accessibility reads use bounded outstanding work and cached results; stale, failed, or unsupported button information hides the panel. Application-button layout events invalidate cached generations; stale in-flight results cannot be reused. Worker completion can trigger placement refresh, while placement availability updates the main-window status. These checks do not introduce per-second state writes.

Microsoft recorded the same platform lookup failure in [windows-dev-docs issue 1431](https://github.com/MicrosoftDocs/windows-dev-docs/issues/1431). This identifies the application's blocking branch, not proof that a banner has appeared on the user's desktop.

The follow-up bug audit reproduced and fixed:

- Backward UTC changes while fully exited capped displayed remaining time at the nominal duration and lost restored time on Pause. Remaining time now follows the saved UTC deadline, including pause/persist/resume when it exceeds the nominal duration.
- Stale temporary-file names caused save failures and deleted pre-existing files that the save did not own. Exclusive creation now retries collisions, and cleanup only removes owned files.
- Global numeric locale could introduce digit grouping into saved JSON. Serialization now uses the classic locale.
- A data-directory path that was actually a regular file silently loaded defaults. Loading now reports the invalid storage path.
- Saving startup settings relied on a cached checkbox state and could leave an old executable registered, or fail to repair an externally removed registration. Explicit Save now reconciles the actual per-user registry value.
- A failed scheduler registration set its error message after the last status paint. The error is now displayed immediately with the window accessible.
